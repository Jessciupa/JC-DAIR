# moral-drift

Do the Moral Machine's cultural clusters change their minds over a 20-year deployment? This folder
is a worked example of **formal verification with [CORA](https://cora.in.tum.de) applied to a
social and ethical question** rather than a safety-critical one. It fits each cluster's
present-day moral preferences from the real votes of
[`moral-classification/`](../moral-classification/README.md), lets them drift under
**Friedkin-Johnsen opinion dynamics**, and asks how long a classifier trained on one cluster's
choices today keeps agreeing with that cluster: its **alignment horizon**.

```
votes.csv.gz -> preference weights per cluster -> 20-year drift -> yearly stay/swerve choices    (generate.py)
                                               -> uncertain linear system -> reachable sets       (cora/moral_drift_FJ.m)
```

Concept
------------
An autonomous car is aligned once, at deployment, and then runs a frozen policy for 15 to 20
years. The people it was aligned to keep changing their minds. Even a policy that is verified
correct today has a horizon after which it may no longer agree with them.

Verifying this looks like collision avoidance:

| Collision avoidance | Moral drift |
|---|---|
| a vehicle's position and velocity | a cluster's preference weights θ_i |
| dynamics with uncertain parameters | Friedkin-Johnsen drift with interval coupling a_ij |
| reachable set of each vehicle | reachable set of all clusters' preferences |
| unsafe set | preferences under which the cluster's choice on a dilemma differs from the frozen classifier's |
| time to collision | alignment horizon: the first time a disagreement becomes possible |

The question is not *will* the clusters change their minds, which nobody can forecast, but *can*
they, under assumptions stated as intervals. A dilemma whose reachable set never reaches a
disagreement is verified aligned for every parameter in those intervals; sampled simulations can
never show that.

Motivation
------------
The position paper *Exploring Verification Frameworks for Social Choice Alignment* (Ciupa, Belle
and Komendantskaya, NeSy 2025) argues that moral dilemmas are not decided in a social vacuum, so
verification should ask whether a model aligns with a group's preferences.
`moral-classification/` verifies that alignment at one moment, against perturbations of the
input. This folder adds time: the input stays fixed and the group moves.

Formal verification is usually applied to safety-critical systems with known physics. Here the
dynamics are a model of society, so the result is only as good as the model, and the folder is
deliberately explicit about which parts come from data and which are assumed.

Installation
------------
From inside `moral-drift/`:
```
uv venv --python 3.11 .venv
source .venv/bin/activate
uv pip install -r requirements.txt
```
It reads `moral-classification/dataset/votes.csv.gz`, `moral-classification/data/dilemmas.jsonl`,
and `decode_side` from `moral-classification/dataset/moral_machine.py`. The CORA script needs
MATLAB with CORA on the path.

```
python generate.py     # fit the preferences, simulate the drift, write data/
python analysis.py     # optional: which way the choices flip, the alignment horizon, figures/
```
Then, in MATLAB, run `cora/moral_drift_FJ.m`.

The model
------------
**Features.** A dilemma is described by φ, the attributes of the characters swerving **saves**
minus those it **kills**, along Awad et al.'s dimensions: more characters, young, female, fit,
high status, human vs pet, lawful, and pedestrians vs passengers.

**Preferences (fitted from data).** Cluster i's share of swerve votes is

    P(swerve) = sigmoid(θ_i · [1, φ])

where the first weight is the action bias (negative: every cluster prefers to stay). θ_i is
fitted by binomial logistic regression on all 124,834 scenarios answered in every cluster. Its
majority matches each cluster's real choice in `dilemmas.jsonl` on 88-91% of dilemmas. Its
standard errors are the radius of CORA's initial set.

**Drift (assumed).**

    d θ_i = γ (−θ_i + Σ_j a_ij θ_j + (1 − Σ_j a_ij) u_i) dt + σ dW

u_i is the cluster's anchor, its preferences at deployment, which keeps it from being carried
all the way to the others' views. The drift is linear in θ, so with a_ij in an interval it is a
linear system with an uncertain matrix, which CORA's `linParamSys` handles.

| scenario | coupling a_ij | meaning |
|---|---|---|
| `baseline` | 0 | no influence: each cluster wobbles around its own anchor |
| `social_influence` | drawn per run from a_c ± a_r | clusters pull towards each other, held back by their anchors |

| parameter | value | source |
|---|---|---|
| θ_i(0), standard errors | fitted | the Moral Machine votes |
| a_ij | a_c ± 30% | **assumption** |
| γ | 0.2 / year | **assumption** |
| σ | 0.01 log-odds / √year per dimension | **assumption**, sampled data only |

Each parameter is one constant in `generate.py` and is exported to `data/cora_params.json`, so
it can be replaced without changing the rest of the pipeline. There are 50 runs per scenario,
with monthly Euler-Maruyama steps recorded yearly.

Outputs
------------
```
data/preferences.json   - fitted θ, standard errors and accuracy per cluster; φ of every dilemma
data/trajectories.csv   - scenario, run, year, cluster and its weights
data/choices.npz        - p_swerve and choice (1 = swerve), shape [scenario, run, year, cluster, dilemma] (not committed)
data/cora_params.json   - x0, x0_rad, a_c, a_r, gamma, sigma, tFinal and the dilemmas, for cora/moral_drift_FJ.m
data/meta.json          - all parameters and the seed
figures/                - swerve share and flips per cluster over time
```
`generate.sample_votes` turns `p_swerve` into synthetic vote counts, for data shaped like the
real votes.

What the example shows
------------
With the default parameters, the sampled choices of a classifier frozen at deployment disagree
with their cluster on more than 2% of dilemmas within 2 to 7 years (median over runs), even
without social influence. The dilemmas that flip are those near 50/50, where a small change in
preferences changes the majority. These numbers follow from the assumed σ and γ and illustrate
the method; they are not predictions.

The CORA script checks the classifier frozen on the eastern cluster against the reachable set
of all 2,295 dilemmas, and reports which are provably aligned for 20 years, which may disagree
and from when, and how much the earliest horizon would gain if each a_ij were known exactly.
Three dilemmas are so close to 50/50 that they are undecided already within the initial set.

Limitations
------------
- **The data.** Moral Machine users are self-selected (young, male, online), the choices are
  stated rather than revealed, and the forced choice between two deaths shapes the answers
  (Bigman and Gray, 2020, *Nature*).
- **Clusters as agents.** Each cluster moves as one unit; disagreement within a cluster, and
  between its countries, is hidden.
- **Model error.** The logistic model is linear in φ and misses about one in ten real majority
  choices, mostly near 50/50, which is also where the drift flips choices.
- **The dynamics.** a_ij, γ and σ are assumptions, and why one culture would listen to another
  on these questions is itself an open question. Results hold for this model and these intervals.
- **Alignment as the target.** Tracking a drifting majority is not obviously what a car should
  do. Some drift, such as towards sparing people of higher status, is arguably something a
  policy should resist; Germany's 2017 ethics rules for automated driving forbid distinguishing
  between people by personal features.
- **Over-approximation.** Reachable sets over-approximate. Wide intervals make every dilemma
  "may disagree", and narrow ones need justifying.

Future work
------------
- **Calibrate the dynamics.** Estimate a_ij from cultural-distance measures (e.g. Muthukrishna et
  al., 2020, *Psychological Science*) or media, trade and migration flows, and γ and σ from change
  between waves of the World Values Survey or European Values Study.
- **Noise as a bounded disturbance.** CORA has no Brownian noise. `cora_params.json` already
  exports σ; adding it as an input set on the preference states makes the reachable set cover
  the same unexplained change the simulation samples.
- **A margin.** A sign flip from 49% to 51% is not a meaningful change of mind. Require a
  conviction margin μ (e.g. 60/40) before counting a disagreement, and compare clusters with each
  other: on which dilemmas can two clusters come to hold strongly opposite majorities?
- **Drivers of change.** Social influence pulls the clusters together. Socio-economic change
  (individualism, rule of law, inequality), linked to the preference weights across countries,
  could pull them apart.
- **Witnesses.** When the reachable set says a disagreement is possible, find a concrete
  parameter setting and trajectory that produces it, and report how extreme that setting is.
- **A real classifier.** Replace the mock classifier with a network over φ, loaded into CORA with
  `neuralNetwork.readONNXNetwork`.
